# SnapText v0.1 验证与限制

2026-09-24。当前仅 SnapText 实现真实输入和识别；其余五款仍为规划，不计为可用工具。

## 修复

1. 本机重复运行复现：`chi_sim` 正常，`chi_sim+eng` 触发乱码语言文件警告，`eng+chi_sim` 正常。改为后者后，三份原有样例再次通过，不再出现该警告。这是经过实测的规避，不声称已修复 Tesseract 内部根因。
2. 将超时与取消覆盖到参数准备阶段；任何正常、失败、取消、超时路径释放已获得的 worker。初始化晚于超时完成时也释放 worker，忽略迟到进度。六项生命周期回归加原有三项，共九项通过。
3. 识别时锁定编辑框和“恢复原文”，避免未完成任务覆盖用户修改；待解码的新图片不能插入正在运行的任务。

## 真实识别

`node scripts/evaluate.cjs` 运行五份自建图片，原始结果见 `ocr-evaluation.json`：

| 样例 | 结果 |
|---|---|
| 清晰英文 | 去空白 CER 0 |
| 清晰中文 | 去空白 CER 0，原文仍有多余空格 |
| 空白 | 正确返回空字符串 |
| 12° 倾斜 | 无有效文字，CER 1 |
| 强模糊小图 | CER 约 0.756 |

CER 指字符编辑距离 / 参考字符数，忽略所有空白但保留标点。这里只是五份合成开发样例，不能外推自然照片准确率。清晰样例成功不抵消困难样例失败。

## 浏览器

已用真实 2000×2000、50 行合成长图进入识别并取消，页面保留图片，取消后允许重试。之前已走通上传文件、实际识别、编辑复制。初始化过程目前不可取消，页面明确提示；120 秒超时以可控 worker 测试覆盖，不声称已实等两分钟在所有浏览器复现。

首版适用于清晰平直的印刷文字，不承诺倾斜、手写、复杂表格、多栏和模糊图片。手机布局检查不能替代低内存手机实机性能验证。

## 公开发布验收

公开地址：https://jaysaly-cn.github.io/everyday/snaptext.html 。代码提交 `8004dcd4e2ea9bf93707d8a2da273a8072d61476`；Pages、Everyday AI、原 Browser demos 三项工作流均成功。共 16 项公开页面、脚本及模型资源与发布前校验值一致。

390×844 视口检查：入口与工具页均无横向溢出，表单单列可操作。此前长图取消后重试成功，3032 字符、3.1 秒。未进行物理手机性能测试。
