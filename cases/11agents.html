01 / 产品形态

从单点工具，走向成体系的增长服务。

11agents.ai 面向企业与创业者，将多个专业增长渠道组织为 Agent 团队。公开产品采用 Builder、Reviewer、Cron 协作机制，连接产物生成、审核与周期执行；品牌资料接入后，使用者可以在审核环节批准或退回交付。

02 / 本人职责

同时考虑怎么卖、怎么建，以及怎么交付。

商业化设计

围绕渠道覆盖、交付内容、审核机制、服务周期与硬件组合，参与定义产品包装。让购买者可以理解得到哪些服务，也让后续运行有对应的交付范围。

产品流程设计

参与梳理品牌与产品 Onboarding、Agent 任务计划、审核队列、发布和周期复盘。把用户决策放在资料输入、产物审核与结果反馈等具体节点。

Agent Builder 建设

围绕 Agent 描述与配置、知识库、Skill Bundle、计划和派发能力开展产品与能力建设，支持专业 Agent 的创建、复用与持续调整。

专业 Agent 开发

将渠道目标、输入材料、输出格式、质量标准与执行周期组织为可运行的 Agent；以生成、审核、周期执行的配合方式管理交付质量。

03 / AGENT BUILDER

把专业要求写进 Agent 的配置与运行方式。

我的 Builder 工作围绕一个具体问题展开：如何让专业 Agent 的目标、材料、能力和计划可以被组织、复用和修改。产品定义需要同时落到配置入口和后续任务执行上。

01

描述与配置：明确角色和交付目标

将渠道目标、输入范围、产物形式和质量要求组织为 Agent 的描述与配置，使专业分工有明确的表达。

02

知识与 Skill：连接材料与执行能力

围绕知识库和 Skill Bundle 建设能力，把品牌背景、任务材料与可复用的执行方式接入 Agent 创建和迭代流程。

03

计划与派发：将能力落实到任务

围绕任务规划、计划与派发开展工作，使专业 Agent 可以按周期承接具体任务，并通过运行管理持续跟进。

04

审核与复盘：保留人工判断

参与审核队列和人机协作设计；结合 GA4 / GSC 等只读指标输入，为交付复盘和后续 Agent 调整提供依据。

04 / 产品流程

从品牌接入，到每一轮交付与复盘。

  1. 01

    接入业务与品牌信息

    梳理目标客户、产品背景、品牌资料和渠道需求，为专业 Agent 提供工作上下文。

  2. 02

    配置能力与任务计划

    组织 Agent 描述、知识库与 Skill，明确任务目标、交付格式与执行周期。

  3. 03

    生成产物并进入审核

    在审核队列中批准或退回内容，让外部发布保留清晰的人工决策节点。

  4. 04

    交付与周期复盘

    结合渠道交付和只读数据指标，回看产物与执行情况，再调整后续任务和 Agent 配置。

05 / 实践与思考

产品承诺，需要与实际运行对应。

这段工作让我把商业化包装和 Agent 运行放在一起考虑：服务范围如何变成任务，质量标准如何进入审核，持续交付如何对应计划与复盘。Agent Builder 既承载能力配置，也连接日常运行中需要不断调整的专业要求。
