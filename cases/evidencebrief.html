01 / 研究流程

先定义问题，再组织证据。

  1. 01

    建立比较框架

    定义研究问题、比较对象和维度，避免只有长篇总结却无法进行产品判断。

  2. 02

    收集来源快照

    采集公开 HTTPS 网页或粘贴原文，保存时间、正文与内容哈希。资料不可变，后续更新以新快照记录。

  3. 03

    关联原文并审核

    候选结论必须关联连续逐字原文，经人工确认后才能进入报告。模型建议不自动批准。

  4. 04

    比较与报告交付

    生成对比矩阵、证据缺口和不同表述复核线索，导出可回查的 Markdown 与 JSON 报告。

02 / 产品取舍

把研究中的不确定性留下来。

原文存在不等于判断正确

引用校验保证可回查，人工审核负责语义、时间与适用条件。没有把字符串校验包装成事实真伪判断。

空白不等于能力缺失

对比矩阵显示“待补证据”，不会把未检索到资料自动写成“竞品不支持”。

不同表述交给人复核

同一单元格出现不同描述时标记复核线索；规则不声称具备语义矛盾检测能力。

旧报告不随资料变更改写

归档来源改变后续报告范围；已生成报告保留当时的证据快照，支持事后复盘。

04 / 当前边界与后续

先把证据工作做好，再增加自主研究。

当前是结构化研究工作台，支持手动提供网址与原文；免费本机模型已验证并保留失败记录，尚未完成自动搜索、循环研究和独立盲审评测。v0.2 支持分段处理、失败重试与持久化覆盖范围，尚无跨段自动综合推理。网页采集支持 HTML / 纯文本，不支持登录页面、PDF 或依赖 JavaScript 渲染的正文。

源码包含启动说明、测试、锁定依赖、Dockerfile 与产品设计文档。代码通过 AI 编程协作完成；尚无真实用户访谈与客户提效数据。GitHub Pages 提供本案例和源码，动态后端需本地启动或另行托管。

v0.2 / 长文处理

来源尾部，也进入研究范围。

新增每段最多3600字符、重叠240字符的分段处理。显示范围、成功与失败状态，支持停止、继续和单段重试；引用须定位在当前段，报告冻结处理覆盖。

4624字符真实本机模型开发样例：第1段协议失败，第2段提取到4590位置的两条候选。只标记1273字符覆盖，价格简述仍遗漏套餐限定，候选未批准。不是全文召回达标，跨段条件仍需人工复核。

v0.3 / 人工修订

修正结论，也保留来路。

审核卡片可查看前后文并高亮原文。修订结论、维度或引用后生成新版本、恢复待审核，不能沿用旧批准；旧报告仍保留原快照。

已实测补齐模型漏掉的团队版限定：v1原候选、v2人工修订、v3重新审核均可追溯。旧记录只从首次变更时记录基线，不补造历史；共享工作台尚无审核人员身份系统。

执行层 / 本机 API 与 CLI

跨资料执行，按步骤留存。

选定来源后建立持久化分段计划，逐步抽取候选、记录失败、显式重试与暂停。重启后识别中断状态，已保存的分段通过缓存复用；不会自动批准结论或完成研究判断。

真实免费模型验收：两份合成资料中，一份两次校验失败，另一份一次成功并保留待审核。命令行遇新失败停止，不无限重试。每计划最多32段，仅本机API/CLI可用，网页调度面板尚未接入，临时公网演示未开放此功能。
