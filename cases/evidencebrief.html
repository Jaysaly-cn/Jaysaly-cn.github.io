01 / 研究流程

先定义问题，再组织证据。

  1. 01

    建立比较框架

    定义研究问题、比较对象和维度，避免只有长篇总结却无法进行产品判断。

  2. 02

    收集来源快照

    采集公开 HTTPS 网页或粘贴原文，保存时间、正文与内容哈希。资料不可变，后续更新以新快照记录。

  3. 03

    关联原文并审核

    候选结论必须关联连续逐字原文，经人工确认后才能进入报告。模型建议不自动批准。

  4. 04

    比较与报告交付

    生成对比矩阵、证据缺口和不同表述复核线索，导出可回查的 Markdown 与 JSON 报告。

02 / 产品取舍

把研究中的不确定性留下来。

原文存在不等于判断正确

引用校验保证可回查，人工审核负责语义、时间与适用条件。没有把字符串校验包装成事实真伪判断。

空白不等于能力缺失

对比矩阵显示“待补证据”，不会把未检索到资料自动写成“竞品不支持”。

不同表述交给人复核

同一单元格出现不同描述时标记复核线索；规则不声称具备语义矛盾检测能力。

旧报告不随资料变更改写

归档来源改变后续报告范围；已生成报告保留当时的证据快照，支持事后复盘。

03 / 实际验证 · 2026-09-23

真实采集，完整走通研究流程。

  • 通过浏览器操作采集 Chatwoot 官方 README，保存 7512 字符的正文与哈希，关联一条官方功能声明并审核生成报告。
  • 20 项自动测试通过，涵盖原文匹配、跨项目边界、审核冲突、来源归档、报告冻结、URL 过滤、重定向与模型失败回滚。
  • 11 项合成工作流评测通过，验证“候选不入报告”“归档不改旧报告”等应用不变量。
  • 未实测 Chatwoot 各渠道功能，未调用真实大模型；上述结果不是模型准确率或商业提效证明。

04 / 当前边界与后续

先把证据工作做好，再增加自主研究。

当前是结构化研究工作台，支持手动提供网址与原文；免费或本地模型可选，尚未完成自动搜索、循环研究和真实模型效果评测。网页采集支持 HTML / 纯文本，不支持登录页面、PDF 或依赖 JavaScript 渲染的正文。

源码包含启动说明、测试、锁定依赖、Dockerfile 与产品设计文档。代码通过 AI 编程协作完成；尚无真实用户访谈与客户提效数据。GitHub Pages 提供本案例和源码，动态后端需本地启动或另行托管。
