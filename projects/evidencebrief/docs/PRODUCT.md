# EvidenceBrief 产品说明

## 目标与场景

面向产品经理、解决方案顾问与业务分析人员：产品选型或竞品分析时，问题通常不是“没有一段总结”，而是无法回查结论的来源、适用时间与适用条件。首版将研究对象、比较维度、资料原文、事实判断与确认状态组织起来。

用户假设尚未通过真实访谈验证。首版不声称全自动调研，也没有真实用户规模或节约时间指标。

## 核心业务流程

研究问题与比较框架 → 来源采集/导入 → 逐字证据 → 候选判断 → 人工确认/退回 → 对比矩阵与资料缺口 → 冻结报告。

模型（可选）只负责建议候选，不拥有确认权限。来源里的指令不作为应用控制指令；接口只接受预定义的比较维度与可查到的原文。若一次模型建议中任一条无效，全部回滚，不产生部分有效的假象。

## 关键产品判断

1. **固定比较维度**：先明确要回答什么，再采集来源，避免只有长篇总结却无法做选择。
2. **原文校验 + 人工确认**：逐字引用校验提供可回查证据，不能代替语义正确性判断；模型建议不默认发布。
3. **缺失不做否定结论**：空单元格显示待补证据，不能变成“竞品不支持此能力”。
4. **不同表述是复核任务**：规则仅比较规范化字符串；“19 元/月”和“月付 19 元”也会提示复核，不声称理解语义矛盾。
5. **来源不可变**：更新网页需保存新快照；旧报告保持引用时的原文。归档改变新报告范围，不改写旧报告。
6. **失败可以继续工作**：站点无法采集时明确报错，提供粘贴来源路径，不偷偷改为虚构材料。

## 数据结构与约束

projects 固定 entities/dimensions；sources 保存实体、原文及哈希；claims 固定来源与引用起点，state/version 控制审核；reports 冻结 JSON + Markdown；events 记录采集、审核、归档及报告生成。

来源重复键为项目+对象+网址+正文哈希。跨项目来源绑定、非连续引用、缺少说明的审核、过期版本覆盖均被后端拒绝。共享令牌只防止未经授权访问，不提供每用户权限。

## 后续验证

让真实求职者/产品同学完成一份两产品三维度研究，观察资料导入成功率、引用关联耗时、审核退回原因与报告可读性。确认痛点后再增加自动搜索、引用定位高亮、报告修订差异与任务队列；免费模型可用时另做真实抽取精度与幻觉测试。
