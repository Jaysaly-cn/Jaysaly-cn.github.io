# 长会议逐段提取 · v0.2

原版只将前4000字符交给模型。现按连续范围划分完整原文，每段最多4000个Python Unicode字符；优先在后半窗口的换行或句末切分，没有边界时硬切并提示。分段之间不重叠、不丢字符。浏览器以Unicode码点切片，避免Emoji使预览与后端偏移不一致。

在会议页选择一段，查看原文范围后显式提取。成功记录按会议哈希、范围和分段版本关联，默认复用，不重复调用；勾选重新调用才会再次运行。失败段可以重试，失败重试不会覆盖此前成功记录。历史仅前缀提取记录没有完整范围凭据，不推定为新分段已完成。原文不可修改，分段v1算法后续若变更须增加版本标识。

本功能逐段按请求执行，不是自动后台队列。关闭页面不会承诺服务端一定完成；刷新后以持久记录为准。没有进程恢复队列或取消接口，多worker不共享模型锁。每次仍最多8个模型候选、会议最多100行动。跨段承诺与缺失发言人上下文可能漏提或被拒绝，用户需查看原文或手工补充。

## 真实模型验收

- 4615字符合成会议，前段3979字符，后段636字符。承诺放在4000字符之后。
- 先请求后段，约4.9秒返回一项候选“完成接口验收文档”，引用“我明天完成接口验收文档。”起于4603，负责人由紧邻发言人前缀小林定位；明天换算为2026-09-24。
- 再请求前段，实际发生ReadTimeout，返回502，留下失败轨迹。系统显示1/2段成功，没有宣称全文完成。
- 浏览器重复提取后段复用原运行；核对承诺、负责人和期限后，人工确认并进入跨会议看板。重启服务再请求该段仍复用，运行数保持2。

原始请求和最终待确认快照：[segment-live.json](../artifacts/segment-live.json)。浏览器确认后状态、重启复用与最终兼容字段：[segment-browser.json](../artifacts/segment-browser.json)。最初真实调用响应的truncated=false在验收中发现不利于旧客户端理解，最终修正为多段会议返回true；没有改写原始实测文件。它表示单次请求只处理一个范围，不表示已成功覆盖的总量。
