# 产品设计

面向项目协作与产品运营：会议纪要中的行动承诺容易缺负责人、相对日期难回查、改期没有记录。本项目先验证从原文到执行状态的闭环，尚未完成真实用户访谈，不能预设节省工时。

已调研 Meetily（https://github.com/Zackriya-Solutions/meetily），官方项目覆盖本地录音、转写和总结，技术栈含 Rust。本项目选择文字输入的会后执行工作台，后续可接转写输出；没有复制其代码，也不宣称拥有其录音能力。复用本作品集已验证的 FastAPI/SQLite 与安全中间件，而非另建账号平台。

工作流：读取快照 → 免费模型候选提取 → 结构/原文/负责人证据校验 → 日期规则解析 → 整批写入 → 人工确认 → 状态跟踪与导出。每次模型调用记录成功/失败、覆盖范围、耗时和审核要求；模型不能调用状态写入接口。它是模型辅助工作流，尚不是自主会议 Agent。

技术决策：

- SQLite 短事务覆盖整批候选，失败不留半成品；模型调用不持有数据库写锁。
- 负责人必须有名字或紧邻发言人前缀证据。原文重复时要求消歧，不随意选第一处。
- 明确日期由规则计算，模糊日期留空。审核人可调整安排，必须记录说明。
- Draft / rejected 不进入任务看板或导出。状态机配合 version 防止多标签页互相覆盖。
- 任务改期保留前后值；完成需要成果说明，重新打开保留事件历史。
- 导出由用户下载，外部系统无自动写入。ICS 按 RFC5545 的文本转义、75字节折行、稳定UID、版本序号和全天日期输出；未声明完成所有客户端互通测试。

下一步：更强免费模型与独立误提取评测、分段全文提取、任务依赖与周报、转写导入的时间戳定位、真实小组试用。先记录漏提与误提，不根据绿色接口测试编造模型效果。
