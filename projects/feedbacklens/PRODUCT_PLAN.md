## 开源选型

- Argilla：https://github.com/argilla-io/argilla 。参考模型建议与人工标注分离的工作流；本次未复制代码或部署。官方 README 当前说明不再新增功能、继续修复问题。因此不把整个服务作为新产品的长期核心依赖。
- RapidFuzz：https://rapidfuzz.github.io/RapidFuzz/Usage/fuzz.html 。实际依赖 3.14.6（MIT）。使用 ratio 的字符相似度，不将其宣称为语义聚类。高相似的否定句仍可能表达相反含义，必须人工确认。
- 复用本作品集 FastAPI/SQLite/免费本地模型适配经验；不将 Argilla 的数据集标注功能包装为我们原创算法。

## 目标流程

1. 导入反馈，保留批次、原文、渠道和原始 ID。重导入不重复计数，ID 冲突整批回滚。
2. 模型提出主题/类型及逐字引用；不能无依据推断用户属性或紧急程度。单条多诉求允许多标签，无法判断时保留待处理。
3. 人工确认主题、拒绝错误建议、检查相似反馈是否确实重复。不同渠道同文不自动合并。
4. 按明确口径汇总主题反馈数、独立来源 ID 数及已确认重复数量，冻结报告时保存证据快照。频次不是需求价值，更不是用户人数。
5. 输出可供需求讨论使用的报告，优先级由用户填写理由，不自动把情绪、字数或模型置信度换算为商业影响。

## 验收门槛

CSV 原子导入、重导入及冲突；相似度反例（仅多一个“不”）；模型单条多诉求、否定、讽刺和嵌入指令样例；人工状态与版本冲突；同一证据多主题不膨胀总反馈数；冻结后导入新记录不改变旧报告；真实模型输出与自动回放分开；浏览器完整操作与手机检查。达成前不加入第九件展品。

四条真实模型合成探针覆盖多诉求、否定、讽刺及嵌入指令：多诉求引用改写被拒；否定样例主题为占位词；讽刺样例提取加载问题；嵌入指令污染草稿主题，但没有确认或发布动作。后两条原始输出有自动回放，验证草稿不进入报告，不等同语义正确性测试。暂不提供自动优先级；报告使用者填写使用说明和判断理由。
