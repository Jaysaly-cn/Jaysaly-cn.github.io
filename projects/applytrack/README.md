# ApplyTrack · 求职证据工作台

个人求职工具：JD 原文 → 要求候选 → 人工审核 → 项目证据关联 → 冻结投递材料 → 阶段与跟进记录。

## 本机启动

Python 3.12，安装 `requirements.txt`。在本目录运行：

```powershell
$env:AT_MODEL_BASE_URL='http://127.0.0.1:8771/v1'
$env:AT_MODEL='portfolio-qwen-1.5b'
python -m uvicorn app.main:app --host 127.0.0.1 --port 8769
```

打开 http://127.0.0.1:8769 。模型可不配置，手工流程仍可用。运行本地模型的方法见作品集 `local-model-runtime/README.md`。另外支持明确的 OpenRouter `:free` 型号；不默认启用收费模型。

SQLite 默认保存在 `data/applytrack.db`；`APPLYTRACK_DB` 可改路径。个人资料和数据库不上传 Git。跨机器运行必须设置 `APPLYTRACK_ACCESS_TOKEN`，但当前无多用户身份或权限隔离，不能当企业招聘系统使用。

## 已实现

- 不可变岗位原文、证据正文、SHA256；来源链接只保存，不主动抓取。
- 模型候选只读前4000字符，显示处理范围；逐字引用定位与重复片段拒绝；失败整批回滚，记录真实模型输出。
- 人工确认职责/必须/优先，修订简述；已审核要求才能关联证据。关联需要证据原文及人工说明。
- 显示有多少要求已关联证据、哪些仍有缺口；不是能力分数或录用概率。
- 冻结 JSON 材料包，投递必须关联同岗位材料包；后续变化不会改写快照。
- 收藏、投递、初筛、面试、Offer、结束状态与版本冲突检查；跟进日期及审计记录。

## 验证与边界

`python -m pytest -q`：13项测试，覆盖材料冻结、引用、关联前置、跨岗位材料、状态、模型回滚、访问保护与持久化。

`python -m evals.live_model`：只允许本机8771，四条合成开发资料；输出在 `artifacts/`。详见 [模型评测](docs/MODEL_EVALUATION.md)。模型会遗漏要求、混淆类型，必须人工补齐，不能自主投递或判断候选人是否适合。

当前没有简历解析、日历同步、邮件读取、自动申请、真实用户效能数据。界面支持逐岗位跟进，逾期筛选已在 API 提供，尚未做前端筛选入口。已审核要求可填写原因撤回，保留历史快照；需新增更完整的原文条目进行替换。证据正文不可原地改写。

API 文档：`/docs`。所有作品集演示资料为合成，不代表真实求职或客户业绩。当前首版本地可用，公开动态托管尚未完成。
